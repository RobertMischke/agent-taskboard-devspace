Review the website people actually use

Start with the running website, follow its navigation and read each statement in context. A useful review connects an observation to the source that needs to change.

A finding needs more than a label

Calling a sentence vague does not tell the next person what information is missing. Name the question a reader cannot answer. Describe the visible behaviour and distinguish it from a claim about quality, speed or reliability. If a claim needs evidence, make that missing evidence part of the feedback.

Keep the surrounding meaning

A shorter sentence is not automatically a better sentence. A rewrite can remove a limitation or add a promise that the original never made. Compare the two versions before applying a change. Ask which facts were retained, which were added and whether the page still answers the reader's question.

Change the responsible source

On a static website, the text may be part of an HTML file. In an Angular application, a route can combine a component template with a content module. Editing the rendered DOM would last only until the next render. The reviewed proposal therefore belongs to the actual source file and its current version.

Verify the result in the browser

After applying the source diff, open the same page again. Check the changed text, nearby links and any other routes that share the component. Keep unresolved questions attached to the project, so the next review starts with the decisions already made.

A deliberately broad statement to review

Our powerful system makes every task effortless.

Select the statement in Voice Studio and propose a description of an observable action. Do not add a performance claim unless you have evidence for it.
