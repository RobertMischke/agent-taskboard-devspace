F1 bug

Aspect-runner falls through to "concerns" silently

All four aspect verdicts (requirement-fit, code-quality, documentation-impact, tests-and-evidence) returned "concerns" with the boilerplate No [[ASPECT_VERDICT]] sentinel was found in the model reply. Auto-review tags are then meaningless — every task ships with three "concerns" tags regardless of real quality.
  • Audit the aspect-runner prompt → does it still ask the model for the [[ASPECT_VERDICT]] pass|concerns|fail sentinel?
  • Check whether Sonnet 4.6 reliably emits the sentinel; tighten the prompt with an example reply.
  • If the parser changed, document it. Add an integration test that runs one real aspect end-to-end and asserts a non-fallback verdict.
  • Until fixed, tag fallback verdicts as review:unparseable not quality:concerns so the UI distinguishes "no real verdict" from "model has a concern".
Acceptance: a fresh task with a clean deliverable lands in 5-human-review with at least one aspect = pass, no default-fallback boilerplate body.
F2 ux

New task is invisible after creation

On a project with 200+ cards in Backlog, the brand-new task lands somewhere in the column with no highlight, no scroll-to, no toast linking to it. Operator has zero feedback that the task went where they wanted.
  • After create-task: 800 ms pulse highlight on the new card + scroll-into-view in its target lane.
  • Confirmation toast bottom-right: "Created "title" in Ready. Open →".
  • If the new card is below the fold, the lane shows a "1 new card" jump-chip at the top.
Acceptance: after submit, the operator's eye lands on the new card within 1 s without scrolling manually.
F3 ux perf

Large boards (200+ cards/lane) have no virtualisation

BACKLOG renders all 201 cards in DOM at once. Lane has no in-place filter, no "recent first" sort, no condensed mode that fits more on screen.
  • Virtualise the lane body (reuse pattern from <app-chat>'s virtual mode).
  • Per-lane mini search field in the lane head when the lane has > N cards.
  • Stash a "compact card" mode at the lane level so a tall lane fits on one screen.
Acceptance: lane with 500 cards renders < 100 ms after project switch; first 20 cards scrolled into view without DOM stalls.
F4 ux

Orchestrator rail clips lane cards instead of reflowing

With the rail open at default width (~640 px), each lane gets only ~80 px. Cards stay full width and clip; the operator has to scroll horizontally inside every lane to see anything.
  • When orchestrator rail is open AND viewport < threshold: auto-engage Compact card mode.
  • Hide lane-group head/labels in compact mode to reclaim vertical space too.
  • Provide a one-click "snap rail to 33% width" affordance on the rail's resize handle.
Acceptance: opening the orchestrator rail never produces clipped card content on a 1600×900 viewport.

Auto-toggle state change has no announcement

Flipping manual ⇄ auto on the titlebar chip only changes a tiny dot + label. Operator can flip it by accident and not notice.
  • Short toast: "Runbook · auto-pickup enabled (2 slots)" / "...paused".
  • Brief animation on the project chip (e.g. accent ring) when the value changes.
F7 ux

Stale chat errors look indistinguishable from live ones

The orchestrator chat showed two-day-old red error bubbles ("claude-code\bin\claude.exe ... not found") from sessions where the npm wrapper was missing. The actual run just now spawned Claude fine. The operator can't tell.
  • Dim or muted-style error bubbles older than one super-phase boundary.
  • Add a "Clear history before session N" affordance to the orchestrator chat head.
  • Optional: when an aspect/runtime issue is resolved (e.g. shim now works), emit a workbench event marking prior errors as "resolved" so the chat can fade them.
F8 bug

Claude tries New-Item on Windows, gets exit 127, retries

Cli-output log shows every Windows session starts with one wasted tool call where Claude reaches for PowerShell's New-Item -ItemType Directory, gets a bash shell that doesn't recognise it, exit 127. Then Claude self-corrects to mkdir -p. Burns one tool call + ~10 s per directory-creation pattern.
  • Add a one-line shell hint to Claude's system prompt: "Shell is git-bash. Use POSIX commands (mkdir -p, cp, rm) — PowerShell verbs are not available."
  • Alternatively: spawn Claude inside a thin wrapper that maps PowerShell verbs to POSIX equivalents.
F9 dx

Lane-group testids drift from state IDs

DOM uses lane-group-backlog / active / decide while job states are 2-ready, 3-progress, 4-auto-review, 5-human-review. Automation has to guess the mapping.
  • Add per-lane testids matching the state id, e.g. lane-state-2-ready alongside the lane-group id.
  • Document the mapping in docs/frontend-testids.md.
